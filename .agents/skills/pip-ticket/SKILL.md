description: Take a Windwords bug or feature from report to a resumable ticket, scoped implementation and verified completion in a Pip’s English checkout.
---

Read repository AGENTS.md and the exact issue. Route through docs/CODE-MAP.md;
load one relevant area guide, not all project docs or old chat history.

If a report has no ticket, write outcome, decisions, reproduction, acceptance
criteria, blockers, exclusions and cheapest tests before coding. Unapproved ideas
stay backlog. User normally delegates ordinary technical decisions, but this skill
never creates permission for spending, secret changes or unrelated releases.

Work one approved issue or explicitly approved batch. Record the branch/claim.
Keep phase/type/word IDs and teacher-directed Learning assumptions. See the audio
and asset guides before paid providers or cropping. No automatic image generation.

Before a pause: update issue with evidence, last commit, dirty files and next step.
Before closure: test the actual behaviour, link commit and state whether pushed /
deployed. Use a stronger model after two failed evidence-based hypotheses, with a
small reproduction packet. Do not forward the entire conversation or spawn paid
helpers without authority. Skill availability is optional: the linked plain docs
are the portable fallback for any AI.
