# Adapted Matt Pocock workflow — not the entire suite on every task

Reviewed the installed engineering catalogue metadata, and read setup, to-tickets,
grilling/grill-with-docs, domain-modeling, codebase-design, architecture review,
implement, triage, handoff and to-spec instructions. Related skills remain available
when useful; they are NOT mandatory dependencies for another AI.

| Skill family | What Pip keeps | What Pip avoids |
| --- | --- | --- |
| setup-matt-pocock-skills / ask-matt | tracker, labels, short glossary and routing | repeated configuration interviews |
| to-tickets / to-issues / to-prd / to-spec | verifiable complete slices, explicit blockers | enormous user-story lists and speculative tickets marked ready |
| grill-with-docs / grilling / grill-me / batch-grill / questionnaire | resolve material choices once, record outcome | asking the teacher to pick ordinary code details |
| implement / tdd / diagnosing-bugs | targeted reproduction, real behaviour tests, one final suite | paid tests, random rewrites, repeated full gates |
| codebase-design / improve-codebase-architecture / design-an-interface / refactor-plan | improve real seams exposed by fixes | splitting every function, framework migration or package scaffolds |
| triage / qa | status, acceptance brief, reproduce reports | duplicate live trackers or closing on assertion alone |
| prototype | isolated demo to answer a question | prototype code silently promoted to production |
| handoff / claude-handoff / wayfinder / loop-me | small resume packet and dependencies | full-context dumps or recursive agents |
| research / to-questionnaire | bounded official-source facts when missing | browsing the whole stack for a local CSS fix |
| setup-pre-commit / setup-ts-deep-modules / shoehorn | only if the project actually needs these tools | TypeScript/package machinery in a plain static game |
| resolving-merge-conflicts / git guardrails | preserve other work; ask on ambiguous destructive choices | reset/force-push as a shortcut |
| ubiquitous-language / domain-modeling | one CONTEXT.md glossary | competing vocabularies |
| wizard / teach | a short bootstrap or teacher walkthrough when useful | a wizard or new dependency for every task |

Project docs override generic workflow preferences where the owner deliberately
adapted them. Tool safety rules and current user permissions still take precedence.
Do not load data URIs, audio packs or full asset catalogues into model context:
inspect sizes/JSON keys first, then select text fields. Large minified lines need
bounded output. Use scripts/inventories for exhaustive checks instead of narration.
